# Техническое задание: Чат

**Версия:** 2.0  
**Дата:** 12 октября 2026  
**Статус:** принято  
**Видимое имя на телефоне:** Калькулятор  
**Скрытая часть:** чат  

Документ — единая постановка. Реализация кода — по отдельной команде, не из факта приёмки.

---

## 1. Продукт

Личный мессенджер с диалогами **1-на-1**. Ориентир по виду и ощущению — Telegram. Групп, каналов, ботов, голосовых, стикеров, звонков нет.

На Android снаружи — **калькулятор**, внутри — чат. Веб не маскируется: обычный чат в браузере. Код калькулятора — отдельный модуль, оболочку можно заменить, не переписывая мессенджер.

Состав:

| Часть | Назначение |
|---|---|
| Android (Kotlin, Jetpack Compose) | основной клиент |
| Веб (Next.js) | компьютер, регистрация, скачивание APK |
| Backend (Python, FastAPI, SQLite) | аккаунты, сообщения, медиа, реалтайм |
| Docker + nginx | выкладка на `daystream.ru` |

Целевая нагрузка — двое активных людей, несколько устройств (телефоны и браузер). Источник правды — сервер.

## 2. Вне скоупа

- Группы, каналы, боты, E2E, исчезающие сообщения, 2FA
- Голосовые, кружки, звонки, стикеры, GIF, реакции, закреплённые сообщения
- Съёмка с камеры (только галерея)
- Регистрация по телефону / email; регистрация из Android
- Публикация в магазинах (только APK по ссылке)
- Маскировка веба
- Другая публичная оболочка вместо калькулятора (калькулятор — в этой версии; код отдельно, чтобы сменить позже)
- PostgreSQL (закладывается абстракция SQLAlchemy, смена БД позже)

## 3. Аккаунты

Регистрация **только** на сайте `https://daystream.ru/extra/chat` или вручную в БД (SQL / скрипт в контейнере backend). Android регистрацию не показывает и API регистрации не вызывает. Форму на сайте не прячем.

- Логин: уникальный, 3–30 символов, латинские и русские буквы, цифры, без пробелов и знаков.
- Пароль: 3–30 символов, русские и английские буквы, цифры, пробел разрешён, **без знаков препинания и спецсимволов**.
- После регистрации на сайте пользователь сразу входит в веб-аккаунт.

Новый диалог открывается **по логину**. Если диалога нет — создаётся при первом сообщении или при открытии карточки. Нельзя написать самому себе.

Глобальное имя = логин. У каждого собеседника свой **ник** («как я его называю»), по умолчанию логин; хранится на сервере, синхронизируется между устройствами. Аватар можно загрузить; иначе заглушка — инициал логина на цветном круге.

## 4. Android: калькулятор, ключ, сессия

Три независимых слоя:

| Слой | Назначение |
|---|---|
| **Сессия устройства** | JWT, FCM, синхронизация. Один раз: логин + пароль на сервер. Живёт, пока не нажали «Выйти» |
| **Калькулятор** | Публичный UI. Обычный запуск иконки / недавних (не чат и не поле ключа) |
| **Страница активации** | Поле ключа. Верный ключ открывает чат |

Ключ = пароль аккаунта. Он прячет чат, а не выключает клиент: в калькуляторе и на активации сообщения принимаются, статусы доставки обновляются, уходит маскировочный push.

### 4.1. Калькулятор

Рабочее приложение, не заглушка. Чат из него не просвечивает. Стиль тот же, что у чата: светлая/тёмная тема, те же шрифты, отступы, цвета панели.

- Иконка и подпись на телефоне — **Калькулятор**.
- Сверху кнопка **«Ввести ключ»** → страница активации.
- Рабочие кнопки: цифры, точка, `+ − × ÷`, равно, сброс, **корень**, **степень** (x^y), **скобки**. Счёт как у обычного калькулятора.
- История последнего входа (лента вычислений) сохраняется и показывается при следующем открытии, пока человек сам её не сотрёт.
- Сложные функции (log, ln, sin/cos/tan и аналоги) **нарисованы, тусклые, не считают**. Нажатие открывает страницу активации, а не включает эти функции. После выхода из чата кнопки снова тусклые.

Код — отдельный Gradle-модуль / пакет, без импорта экранов чата. В чат — узкий колбэк «ключ принят».

### 4.2. Страница активации

Один экран для кнопки «Ввести ключ», тусклых функций и тапа по push (если не действует окно 5 минут, п. 6.3). Выглядит как активация функций / обновления калькулятора, не как вход в мессенджер.

- Первая привязка устройства: логин + ключ. Сервер проверяет, сохраняются JWT, FCM-токен, локальный хеш ключа.
- Дальше: только ключ (логин помнится). Проверка локальная, сессию не рвёт.
- Верный ключ: диалог ровно один — сразу переписка; иначе (нет диалогов или их несколько) — список чатов.
- Неверный ключ: **«Неверный ключ»** (допустимо «Активация не прошла»). Без слов «чат», «пароль», «сообщение». Нет счётчика попыток, блокировки ввода и «мессенджерной» тряски.
- Пароль на диске в открытом виде не хранится (только хеш ключа и защищённые токены сессии).

После «Выйти» человек оказывается в калькуляторе; фон и push останавливаются, снова нужен логин + ключ на сервер.

### 4.3. Сессия и доставка

Сообщения доходят независимо от того, сколько человек не открывал чат. 5 минут из п. 6.3 — только про UI, не про доставку.

- Сессия **не истекает по времени и не сбрасывается из‑за простоя**. Штатный сброс — «Выйти» (позже — смена пароля на сервере, если появится).
- JWT: access 15–30 мин; refresh без срока (или ~10 лет). Фон обновляет access сам, без поля ключа.
- FCM-токен привязан к сессии устройства, обновляется при смене токена Google.
- Телефон выключен / без сети — сообщения ждут на сервере и догоняют при связи.
- «Выйти» инвалидирует refresh и снимает FCM.

После перезагрузки, пока сессия жива, связь поднимается **сама**, без открытия приложения: токены, refresh access, FCM, WebSocket, догон сообщений. Калькулятор, активация и чат не показываются. Push «Доступно новое обновление» после ребута работает как обычно. Отдельного «чат подключился» нет. Если нужен foreground-сервис — канал «Обновления», без намёка на мессенджер. После «Выйти» автозапуск не делается.

После входа в чат подтягиваются последние сообщения диалога и их медиа (п. 7), не весь архив и без блокирующего экрана.

## 5. Веб

Регистрация и вход. Сессия браузера после логина; пароль снова при новой сессии браузера. Калькулятора и замка поверх вкладки нет.

Несколько устройств одновременно допустимы.

Push на вебе не обязателен: достаточно WebSocket, пока вкладка открыта.

## 6. Чат

Интерфейс чата — **максимально близко к Telegram** (не копия исходников): список, шапка, пузыри, поле ввода, скрепка (галерея и файлы), отправка, цвета и типографика в духе TG. Язык — **только русский**. Светлая и тёмная темы, выбор хранится на устройстве.

Веб: список слева, переписка справа (как Telegram Desktop / Web). В узкой вёрстке стрелка ведёт к списку обычным кликом; удержание не нужно.

### 6.1. Список чатов

Экран как в Telegram: сверху поиск / заголовок, список диалогов.

В строке: аватар, имя (ник или логин), точка «в сети»; превью последнего сообщения (текст; для медиа/файла — «Фото», «Видео», имя файла); бейдж непрочитанных (ноль — без бейджа); время; вместо превью может быть «печатает…».

Открытие диалога помечает сообщения прочитанными (синие галочки у собеседника).

На вебе при одном диалоге список слева можно оставить, справа сразу открыть переписку.

### 6.2. Переписка

- Текст и системные эмодзи с клавиатуры ОС. Отдельной панели эмодзи нет.
- Галочки: одна — на сервере; две серые — доставлено на устройство собеседника; две синие — прочитано.
- Ответ с цитатой; правка своего текста и подписи к медиа (пометка «изменено»); удаление своего или чужого **у обоих** (варианта «только у себя» нет).
- «Печатает…».
- Last seen в шапке, как в Telegram: «в сети», «был(а) только что», «был(а) 5 минут назад», «был(а) в 14:03» / «вчера в 21:10». Скрытия last seen нет.
- Подгрузка истории прокруткой вверх.

**Шапка Android:** слева стрелка, аватар, имя, статус; справа три точки (настройки диалога). На списке чатов стрелка / «назад» тоже закрывает приложение; три точки справа — настройки. Пункта **«Список чатов» нет**.

| Жест стрелки / системного «назад» на списке или в диалоге | Действие |
|---|---|
| Короткое нажатие | **Закрыть приложение**: сразу предыдущее в стеке задач, UI чата закрыть в фоне. Без вспышки калькулятора и активации. Процесс не убивать (`System.exit` нельзя): сессия, фон, push живут. Превью в недавних сразу заменить на калькулятор |
| Удержание | Список диалогов, человек остаётся в чате |

Из полноэкранного фото/видео или профиля «назад» сначала закрывает этот экран.

Короткое нажатие — не сворачивание. Таймер 5 минут не включается, в тот же чат по таймеру не возвращаемся.

**После стрелки:** иконка / недавние — калькулятор; уведомление — страница активации. После верного ключа: один диалог — сразу он, иначе список.

«Выйти» — пункт в настройках, не путать со стрелкой.

### 6.3. Сворачивание и 5 минут

Home / недавние / другое приложение при открытом чате — не стрелка. Таймер **5 минут**.

| Возврат | Что видно |
|---|---|
| В течение 5 минут | Тот же экран чата (список / диалог / профиль) |
| После 5 минут | Сразу калькулятор, без кадра переписки даже на мгновение |

Скрытый UI снимается **до первого кадра**. В недавних всё это время — скриншот **калькулятора** (не чат, по возможности не чёрный кадр), иконка и подпись — «Калькулятор». Если на прошивке снимок не подменить — убрать карточку из недавних (`finishAndRemoveTask` / `excludeFromRecents`). Проверить на AOSP, Samsung, Xiaomi.

Пока открыт чат, система не снимает этот экран в превью.

- В окне 5 минут: иконка, недавние **или уведомление** — сразу чат (для push — диалог этого сообщения).
- После 5 минут или после стрелки: иконка / недавние — калькулятор; **уведомление — страница активации**, не калькулятор.
- Сессия, фон и push от сворачивания не рвутся.

### 6.4. Уведомления (Android)

FCM, когда приложение свёрнуто, закрыто или открыто в калькуляторе / на активации.

- Текст: **«Доступно новое обновление»**. Имени, превью и текста переписки нет.
- Канал нейтральный, например «Обновления». Без слов «чат», «сообщение», «Telegram».
- Тап: в окне 5 минут — сразу чат; иначе — страница активации (не калькулятор и не переписка).
- Звук и вибрация — системные по умолчанию.

## 7. История на устройстве и на сервере

| Где | Что |
|---|---|
| Сервер | Вся история и все вложения |
| Телефон / браузер | Последние **1000** сообщений каждого диалога |

При открытии чата запрашивается хвост, не архив с первого дня. Прокрутка вверх — страница с сервера (пока человек в экране, она может быть в памяти). После выхода из диалога и периодически в фоне локальная база обрезается до 1000. Вложения на телефоне — только у сообщений в этом окне; вытесненные скрытые файлы удалять.

Цитата ответа хранится в новом сообщении, даже если оригинал уже вытеснен. Правка и удаление на сервере полные.

Веб: IndexedDB / память, не качать весь архив.

## 8. Фото, видео, файлы

Ориентир — Telegram: сжатые фото и видео, смешанные альбомы, просмотр на тёмном фоне на весь экран. Не документ вместо фото и не кружки.

### 8.1. Отправка медиа

Только из галереи (на вебе — выбор файлов). За раз 1–10 вложений, можно смесь, альбом как в TG, опционально подпись.

- Фото до сжатия ≤ **10 МБ**: JPEG, PNG, WEBP, HEIC (если платформа декодирует).
- Видео до сжатия ≤ **100 МБ**: MP4, MOV, WEBM, 3GP, MKV. Иначе отказ с понятной ошибкой.

### 8.2. Сжатие фото (на клиенте до загрузки)

| Параметр | Значение |
|---|---|
| Контейнер | JPEG (PNG / WEBP / HEIC конвертировать; прозрачность PNG — белый фон) |
| Макс. сторона | 1280 px |
| Качество | 80; субдискретизация 4:2:0; EXIF / GPS удалять |
| Если всё ещё > 10 МБ | качество 60; если не помогло — отказ |

Сервер проверяет MIME, размер и что это изображение; повторно не перекодирует, мусор отбрасывает.

### 8.3. Сжатие видео

На Android — на клиенте. На вебе, если браузер не тянет перекодировщик — **ffmpeg в backend** с теми же параметрами.

| Параметр | Значение |
|---|---|
| Контейнер | MP4, H.264 (yuv420p), AAC ~48–64 кбит/с |
| Макс. сторона | 640 px |
| FPS | не выше 30 |
| Битрейт | ориентир 400–600 кбит/с |
| Метаданные / GPS | удалять |
| Превью | JPEG-кадр для пузыря |
| Если после сжатия > 25 МБ | 480 px / ниже битрейт; если не помогло — отказ |

Сервер проверяет MP4/H.264. В контейнере backend нужен ffmpeg.

### 8.4. Лента и просмотр

- 1 фото — крупное в пузыре.
- 1 видео — превью, play, длительность; **в пузыре не играет**.
- 2–10 — сетка-альбом как в TG (2 колонки; для 3 — типичная раскладка TG); у видео в ячейке play и длительность, без автозапуска; скруглённые углы, единый блок; подпись под блоком, если есть.
- Пока качается — прогресс на превью.

Нажатие — полноэкранный просмотр на тёмном фоне: листание соседних фото и видео **этого чата**, закрытие свайпом вниз / «назад». Фото — щипок. Видео играет здесь (play/pause, звук, перемотка).

**«Сохранить»** — обычная копия JPEG/MP4 в Pictures / Movies. Скрытая копия в хранилище чата не меняется. На вебе «Сохранить» — обычное скачивание.

### 8.5. Файлы

Отдельные сообщения-документы, не альбом и не сжатие как медиа. Скрепка → «Файл». Формат любой; сервер не разбирает содержимое, принимает blob. Один файл ≤ **50 МБ** исходника. Клиент не перекодирует файл как фото/видео.

Gzip на клиенте до отправки: если выигрыш **≥ 10%** — грузить сжатое (флаг gzip); иначе исходник. Сервер второй раз не сжимает. В пузыре — исходные имя и размер. Клиент при скачивании разжимает при необходимости.

Несколько файлов за раз — каждое отдельным сообщением. Можно подпись. Пузырь: иконка, имя, размер, прогресс.

Нажатие само не открывает файл чужим приложением. **«Сохранить»** — рабочая копия в «Загрузки» / системный пикер. Опционально «Открыть»: временная копия через FileProvider, без MediaStore, затем удалить.

### 8.6. Скрытие на телефоне

Вложения чата не попадают в Галерею, Google Фото, проводник и MediaStore. Не DCIM / Pictures / Downloads.

- Приватное хранилище приложения; `.nomedia`.
- На диске не оригинал: чужое расширение, испорченные сигнатуры (свой заголовок и/или XOR). Случайные имена; исходное имя только в БД и в пузыре.
- В MediaStore не регистрировать. Превью в ленте — из тех же скрытых данных.

Показ в чате: снять обфускацию в памяти или во временный cache и сразу удалить. С root / выгрузкой `/data/data` файлы можно украсть; это не банковское шифрование.

## 10. APK, help, README

Магазинов нет. Установка — скачать APK, неизвестный источник.

- `https://daystream.ru/extra/chat/install` — без входа, можно переслать: кратко как поставить и кнопка скачивания.
- `https://daystream.ru/extra/chat/chat.apk` — прямая загрузка, без авторизации. MIME `application/vnd.android.package-archive`, заголовок на скачивание файла.
- Пути стабильные; актуальный APK кладётся при выкладке (статика сайта или volume). `applicationId` и ключ подписи фиксируются, `versionCode` растёт: новый APK встаёт **поверх**, данные (логин, сессия, скрытые файлы, история калькулятора) остаются. Подпись на домашнем экране — **Калькулятор**.

`https://daystream.ru/extra/chat/help` — без входа, в Android не светить: ссылки на чат, API, install, APK; как зарегистрировать человека; как ставится приложение (снаружи калькулятор, чат за ключом); Docker (`extra_services`, сервис `chat`); volume SQLite и загрузок; Firebase / `google-services.json`.

`README.md` в корне — то же плюс команды compose, пересборка APK, куда класть `chat.apk`. Полное задание — этот файл (`TZ 2.md`).

## 11. Стек

| Слой | Выбор |
|---|---|
| Backend | Python 3.12, FastAPI, SQLAlchemy 2, SQLite WAL в том же контейнере |

## 12. Адреса и прокси

Домен: `https://daystream.ru`. Веб **не** кладётся под `/api`.

| Что | URL |
|---|---|
| Веб | `https://daystream.ru/extra/chat` |
| Установка | `https://daystream.ru/extra/chat/install` |
| Help | `https://daystream.ru/extra/chat/help` |
| APK | `https://daystream.ru/extra/chat/chat.apk` |
| REST | `https://daystream.ru/extra/chat/api` |
| WebSocket | `wss://daystream.ru/extra/chat/api/ws` |
| Медиа | `https://daystream.ru/extra/chat/api/media/...` |

FastAPI — префикс `/extra/chat/api`.

HTTPS уже на хосте. Проект свой TLS не поднимает.

**Nginx проекта** (контейнер, порт 80 только внутри Docker, имя сервиса `chat`, порт на хост не публиковать): `/extra/chat` → Next.js, `/extra/chat/api` → FastAPI, WebSocket Upgrade, `client_max_body_size` 64m, отдача APK, таймауты под файлы и долгий сокет.

Сеть как у keepcopy — уже существующая внешняя:

```
networks:
  extra_net:
    external: true
    name: extra_services
```

Хостовый nginx в той же сети:

```
location /extra/chat/ {
    proxy_pass http://chat:80/extra/chat/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    client_max_body_size 64m;
}

location = /extra/chat {
    return 301 /extra/chat/;
}
```

Другие сайты не трогать. Новую overlay-сеть не создавать.

### CI/CD

Репозиторий GitHub, ветка `master`, схема как KeepCopy:

```
push в master
  → CI (compose config, build, nginx -t)
  → SSH на сервер
  → git reset --hard origin/master
  → docker compose up --build -d
```

Секреты: `SSH_HOST`, `SSH_USER`, `SSH_PORT`, `SSH_PRIVATE_KEY`, `DEPLOY_PATH` (по умолчанию `/var/www/Diary-project/TG-chat`, уточняется при выкладке), опционально `DEPLOY_BRANCH`.

До первого pipeline на сервере: клон в `DEPLOY_PATH`, сеть `extra_services`, хостовый `location /extra/chat/`, `git fetch` без пароля.

## 13. Модель данных

- **User** — логин, хеш пароля, аватар, last_seen, FCM-токены устройств.
- **Dialog** — два участника, уникальная пара, дата создания.
- **ContactAlias** — ник собеседника.
- **Message** — диалог, автор, тип (text / photo / video / album / file), текст, reply_to, edited_at, deleted_at, статусы доставки и прочтения.
- **Attachment** — JPEG, MP4 или произвольный файл (имя, MIME, размер), превью и длительность видео, порядок в альбоме.

Удалённое сообщение исчезает у обоих, плейсхолдер «сообщение удалено» не обязателен.

## 14. Безопасность

Уровень средний: личная переписка, не банковские данные.

- HTTPS на входе; внутри Docker до nginx проекта — HTTP.
- Пароли на сервере: Argon2 или bcrypt. Ограничений на объём логов нет; пароль в логи всё же не писать. Прямого доступа к SQLite снаружи контейнера нет.
- JWT до «Выйти»; калькулятор и закрытие UI сессию не рвут.
- Переписка на сервере ключом пользователя **не** шифруется. Локальная БД на телефоне доступна процессу приложения — иначе фон за калькулятором не примет сообщения.
- CORS только на свой origin.
- Файлы: ≤ 50 МБ, случайные имена, без listing; приложение само исполняемые не запускает.
- Перебор ключа на телефоне лимитом не ограничиваем.
- API регистрации доступен тому, кто знает URL — приемлемо для личного проекта.

## 15. Нефункциональные требования

- Доставка в открытом чате: обычно < 1 с в нормальной сети.
- История: на сервере полная; на клиенте окно 1000 сообщений на диалог, старше — пагинация с сервера, без подвисания.
- Одновременно небольшой десяток устройств; целевая нагрузка — двое активных.
- Перезапуск контейнера не теряет БД и файлы (volume). Обрыв сети: клиент переподключает WebSocket и догоняет сообщения.
- Android 8+, веб — актуальные Chrome / Firefox / Edge на компьютере.

## 18. Приёмка

- Аккаунт — на сайте или в БД; в Android только вход.
- Два человека находят друг друга по логину, пишут с телефона и из браузера.
- Локально ~1000 последних сообщений диалога; на сервере история полная.
- Снаружи калькулятор. Вход в чат — активация. Неверный ключ — «Неверный ключ». Один диалог — сразу он. Сессия не истекает; после ребута связь сама; за калькулятором сообщения доходят (статус «доставлено»).
- Push «Доступно новое обновление». Тап в окне 5 минут — чат; иначе — активация.
- Галочки, reply, правка, удаление у обоих, «печатает…», last seen.
- Альбом до 10 фото/видео, сжатие как выше; видео в пузыре не играет, на тёмном фоне на весь экран — да. Медиа чата не видно в галерее и сканерах; «Сохранить» даёт обычную копию.
- Файлы любого формата до 50 МБ; gzip на клиенте только при выигрыше; на телефоне скрыты так же; «Сохранить» даёт обычную копию.
- Стрелка: короткое — предыдущее приложение; удержание — список. После стрелки иконка — калькулятор, уведомление — активация.
- В недавних нет скриншота чата. Сворачивание: 5 минут — тот же чат; потом — сразу калькулятор.
- Калькулятор считает (корень, степень, скобки), помнит историю; тусклые функции ведут на активацию. Веб без маскировки.
- Светлая и тёмная тема.
- `/install`, `/chat.apk`, `/help`, README.
- Контейнеры, хост проксирует `/extra/chat`. Push в `master` выкладывает на сервер по SSH.
